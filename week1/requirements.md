## 1. アプリの概要・目的

- アプリ名：未決定。
- 目的（決定済み）：異なる言語を話す友人同士が、外部の翻訳アプリへ文章をコピーする手間なく、日常的な雑談をできるようにする。
- 概要（決定済み）：チャットと日英の自動翻訳を統合したWebアプリ。各参加者が自分の読む言語を選び、その言語で相手のメッセージを読む。
- 最優先事項（決定済み）：アプリの完成。ES提出期限に合わせた計画や、ES用の開発経験・コード量等の整理は後回しにする。

## 2. 対象ユーザー

- 対象ユーザー（決定済み）：日本語話者と英語話者。
- 将来の方向性（本人の追加希望）：対応言語を増やす。現行版の翻訳・選択肢は日英のみ。紹介文は日英専用を強調しないが、他言語をすでに使えるとは案内しない。
- 利用シーン（決定済み）：海外の友人同士による日常的な雑談。
- 利用方法（決定済み）：双方がこのWebアプリを開いて会話する。
- 対応環境（決定済み）：最初の版はPC版Chromeを使う。
- 開発時の説明方針（決定済み）：利用者本人をIT初学者として扱い、専門用語や判断理由を説明する。

## 3. 基本機能（最初に完成させる範囲）

以下は決定済み。グループ会話は最初の範囲に含まれ、後付けの拡張扱いにはしない。

| 機能 | 利用者ができること |
|---|---|
| 部屋の作成 | 部屋を作ると、ルームID（招待ID）が自動発行される。 |
| 部屋への参加 | 友人から伝えられたルームIDを入力して参加する。 |
| 表示名の入力 | アカウント登録をせず、表示名を入力して参加する。 |
| 画面の表示言語の切り替え | ホーム画面で日本語・英語を切り替えられる。 |
| サイドバーの幅調整 | チャット画面でルームID・メンバーを表示するサイドバーの幅を変更できる。 |
| メッセージを読む言語の選択 | 入室時に、日本語・英語から自分が読む言語を選ぶ。ホームで表示言語を切り替えた際は、読む言語も同じ言語を自動選択する。その後の手動変更は可能。 |
| テキストチャット | 2人でも複数人でも、同じ部屋でメッセージを送受信する。 |
| 入退室 | 部屋に参加・退室でき、参加者を画面で確認できる。 |
| 自動翻訳・原文表示 | 受信メッセージは選んだ言語で表示し、「原文を見る」で元の文章を確認する。 |
| 会話履歴 | 退室後も履歴を残し、同じIDで再入室すると以前の会話を読める。IDを共有された参加者も過去の会話を読める。 |
| 翻訳できない場合の継続 | 翻訳の準備中・失敗等の状態を伝え、原文での送受信を続けられる。 |
| 2画面構成 | 入室画面とチャット画面を使う。詳細は基本設計書に記載する。 |

## 5. データ項目（何を記録するか）

履歴保存は決定済み。次の分類・項目はそれを実現するための**設計案**であり、確定したデータベース仕様ではない。

| 分類 | 項目の案 | 目的 |
|---|---|---|
| 部屋 | 内部ID、ルームID、作成日時 | 会話を部屋ごとに区別し、IDで参加できるようにする。 |
| 参加者 | 内部ID、所属する部屋、表示名、読む言語 | 誰の発言か、どの言語で表示するかを扱う。 |
| メッセージ | 内部ID、部屋、送信者、原文、送信日時 | 発言を保存し、再入室時に履歴を表示する。 |

- 会話の保存期間・削除方法、部屋の有効期限は未決定。退室後の保存に合意したことを、永久保存の合意とは扱わない。

## 6. 制約条件

### 決定済み

- 画面：HTML / CSS / JavaScript。
- サーバー：Java / Spring Boot。
- データ保存：PostgreSQL。
- 実行環境：本人がDockerの追加負担を了承し、ローカルでもDockerを使用する方針を決定。アプリとDBをDocker Composeで起動し、会話履歴をコンテナと別の保存領域に残す。従来の履歴は別途維持し、自動移行しない。
- 処理の自動テスト：JUnit。
- 翻訳：PC版Chromeの内蔵Translator APIを使う方針。
- 翻訳費用：0円。翻訳サービス利用のためのクレジットカード登録も避ける。
- 開発場所：まず本人のPC内で構築する。Java用の具体的な準備方法は開発開始時に説明する。
- 将来の方向性：GitHubでコードを管理・公開し、クラウドでアプリを公開する。公開先は未確定で、Vercelは候補として挙がっている。
- 進め方：質問は原則1つずつ。提案と合意を分け、仕様を無断で確定しない。
- ファイル編集は了承後に行う。実装・依存パッケージ導入・環境構築は、本人が明示的に開発開始を指示してから行う。

### 条件の確認が残るもの

- Chromeで日英双方向の翻訳と初回の翻訳用データの準備を確認済み。口調が不自然になる例があり、翻訳品質の利用者による評価は残る。
- 公開候補はVercel Hobbyのコンテナ実行とNeon Free。本人のVercel希望を踏まえ、現行のJava構成を維持する。無料枠・アカウントでの利用可否・実動作を確認してから公開完了とする。比較と手順は `../DEPLOYMENT.md` に記載。
- アカウント登録がないため、表示名は本人確認の保証にならない。
- ルームIDを知る人は過去の履歴も読める。IDの発行・照合・保護の詳細は設計で詰める。

## 7. 完成の目安

基本機能は第3章で決定済み。以下は検証の観点。2026年10月18日に、実際のPostgreSQLを使うJUnit 10件と翻訳処理のJavaScriptテスト3件が成功し、Chromeで日英双方向の会話・原文表示・複数人の参加・退室・再入室・サーバー再起動後の履歴を確認した。本人の使用確認や、会話全般の翻訳品質の保証を意味しない。

- 複数のブラウザ画面で同じ部屋に参加し、日本語・英語の双方から会話できる。
- ルームIDの共有、表示名・言語選択、参加・退室までの一連の操作ができる。
- 選択した言語で受信内容を読み、必要時に原文も確認できる。
- 再入室後に以前の会話を読める。アプリ再起動後の保存状態も確認する。
- 翻訳の準備や失敗により、メッセージ送受信全体が止まらない。
- 別の部屋の会話が混ざらず、不正なルームIDや空欄入力等を適切に扱う。
- ローカルでの完成と、クラウドへの公開完了を分けて報告する。
