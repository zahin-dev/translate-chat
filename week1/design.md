## 1. 画面設計

### 入室画面（決定済みの構成）

- 入力：表示名、自分が読む言語（日本語・英語）、参加時のルームID。
- 操作：右上の「日本語 / English」で画面の表示言語を切り替えると、メッセージを読む言語も同じ言語に自動選択する（本人の追加修正）。読む言語だけを後から手動変更することも可能。表示言語は日本語を既定とし、両方の選択をブラウザに保存する。切り替えても入力内容・作成／参加の選択を保持する。入室中は、その参加情報の読む言語を維持する。
- 操作：「部屋を作る」または「ルームIDを入力して参加」。
- 作成時：アプリがルームIDを自動発行し、チャット画面で確認できるようにする。
- アカウント登録・ログイン画面は設けない。
- 本人の修正依頼：紹介文は対応言語を限定しない表現にし、主見出しは「慣れた言語で話そう！」、補足は自動翻訳チャットだと分かる文言にする。Chrome・初回ダウンロードの案内はホームから外す。
- 余白の使い方は本人が「会話例を主役にして、翻訳される様子をもっと見せる」を選択。その後の修正で、紹介の補足文・会話例の宣伝見出し・翻訳の流れを説明する文は削除。実際のチャットと共通の吹き出し、名前・時刻、原文表示を使って3発言の会話例を載せる。表示する会話は架空の例で、利用者の実際の履歴を転用しない。
- 日英の固定文言89項目を対照確認。日本語画面の英語見出し、英語だけに加わっていた説明、操作説明の訳、言語名・参加者の言語表示、読み上げラベル等を修正。日英のキー差分とHTML・JavaScript参照先の欠落は0件。Chromeで会話例の原文表示、切り替え時の読む言語の自動選択、再読み込み後の保持、名前・ルームID・参加モードの保持、英語での入室・退出確認を検証した。読む言語の手動変更と保存、日本語へ戻した際の自動選択も確認。ブラウザのエラーログはなし。

### チャット画面（決定済みの構成）

- 表示：ルームID、参加者、会話履歴、翻訳文、翻訳状態。
- 操作：文章の入力・送信、「原文を見る」、退室。
- 本人の修正依頼：サイドバーと会話の境界をドラッグして幅を変更する。初期実装は左右キーでも調整可能とし、ダブルクリックで既定幅に戻す。幅を同じブラウザに保存し、画面が狭くなった場合は会話領域を残す範囲に制限する。
- 修正後のChrome確認：ドラッグで274pxから394pxへ拡張、再読み込みで394pxを復元、キーボードで最小180px・最大480pxへ変更、ダブルクリックで既定264pxへ復帰。表示領域640×360では保存幅を320pxに制限し、会話欄312pxと画面内の入力欄を確保した。ホームは日英両方の文言と案内削除を確認し、幅400pxの英語表示に横方向のはみ出しはなかった。ブラウザのエラーログはなし。
- 受信メッセージは選択した言語で表示する。原文へのアクセスを残す。
- 翻訳の準備中・失敗時は状況を伝え、原文で会話を続けられるようにする。

### 表示・操作の補足案（未確定）

- 会話には送信者の表示名と日時を添える。
- 翻訳の初回ダウンロード中に進行状況を表示する。
- 不正なルームIDや空欄等の入力エラーを、その場で分かる文章で伝える。
- 初期実装：本人の発言は原文。同名の参加者には識別子の一部を添える。言語は入室時に選択し、画面更新ではそのタブの参加情報を復元する。入室中の言語変更は設けていない。
- 別の編集画面・削除画面・追加機能専用画面は、現時点の合意範囲に含めない。

## 2. データ設計

### 保存方法（決定済み）

PostgreSQLを使う。配布ひな形の「JSONファイルに保存する」前提を置き換える。JSONでの通信形式を使うかは、保存方法とは分けて設計する。

### 保存する情報の分け方（提案）

| 分類 | 項目の候補 | 関係 |
|---|---|---|
| 部屋 | 内部ID、参加用ルームID、作成日時 | 参加者とメッセージを部屋単位で分ける。 |
| 参加者 | 内部ID、部屋のID、表示名、読む言語 | 発言者を表示名だけに頼らず識別する案。本人確認用アカウントとは異なる。 |
| メッセージ | 内部ID、部屋のID、送信者のID、原文、送信日時 | 部屋と発言者を関連付け、会話を保存する。 |

- 初期実装：部屋・参加者の内部IDはUUID、メッセージは連番。日時はタイムゾーン付きで保存する。実際の項目は `src/main/resources/schema.sql` を参照。
- 初期実装：参加者にランダムな参加トークンを発行し、DBにはそのハッシュ値を保存する。部屋とトークンを照合し、表示名だけで発言者を決めない。
- 初期実装：最終通信から45秒間通信がない参加者を参加中一覧から外す。明示的な退室ではトークンを無効化し、発言者情報は履歴用に残す。再入室では新しい参加者IDを発行する。
- 初期実装：ChromeのLanguage Detectorで入力言語を判定し、利用不可・短文で不明確な場合は文字種で補う。入力言語は読む言語と分けて保存する。日英混在等の精度には限界がある。
- 初期実装：原文はDBに保存し、翻訳結果はブラウザのメモリに一時保持する。原文と読む言語が同じ場合や、文字を含まない文章では翻訳を省略する。
- 退室後も履歴は残す。削除・部屋の有効期限・保存期間は今後決める。

## 3. 画面遷移

決定済みの基本フロー：

1. 部屋を作る人：入室画面 → 表示名・読む言語を選択 → 部屋を作成 → チャット画面でルームIDを確認 → SNS等で友人に伝える。
2. 参加する人：入室画面 → 表示名・読む言語・ルームIDを入力 → 参加 → チャット画面。
3. 会話：入力 → 送信 → 同じ部屋の参加者が受信 → 必要に応じて翻訳 → 選択した言語で表示 → 原文も確認できる。
4. 退室・再入室：チャットから退室 → 同じルームIDで参加 → 過去の会話を確認できる。

初期実装：退室後は入室画面へ戻る。失敗はその画面で案内する。タブの再読み込みでは参加を再開し、明示的な退室後は新しい参加者として入る。

## 4. 使用する技術

### 決定済み

| 技術 | 役割 |
|---|---|
| Java / Spring Boot | 入退室、部屋・メッセージの処理、履歴の保存・取得。 |
| HTML / CSS / JavaScript | 入室画面・チャット画面の表示と操作。 |
| PostgreSQL | 部屋と会話履歴等の保存。 |
| JUnit | サーバー側の処理の自動テスト。 |
| Chrome Translator API | PC版Chromeの端末内で日英翻訳を行う。 |

### 構成案

- Spring Bootの1つのアプリから画面を配信し、部屋・参加・会話を処理する窓口も用意する。
- JavaScriptがメッセージを受け取り、利用者のPC内の翻訳機能で表示する文章を作る。
- 原文の送受信・保存にはアプリのサーバーとデータベースを使う。翻訳が端末内でできることを、チャット全体がオフラインで動くという意味にはしない。
- 初期実装：2秒ごとに新着の追加分を取得する。最初は最近100件を表示し、以前の会話を追加取得できる。
- 使用環境：Temurin Java 21.0.12.1、Spring Boot 3.5.16、Maven 3.9.16、PostgreSQL 18.6。道具は `.tools/`、DBは `.local/` に配置し、アプリとDBはループバックアドレスで起動する。
- DB操作にはSpring JDBCとPostgreSQL JDBCを使い、画面は静的ファイルとしてSpring Bootから配信する。
- 本人の次段階への移行指示を受け、Gitで完成時点のコードを記録し、GitHubで公開する準備へ進む。過去の開発履歴を後から作ったものとは扱わない。
- Python用の仮想環境は、このJava構成の準備手順として自動採用しない。

### 翻訳方式の影響

- 外部翻訳サービスの契約・カード登録を必要としない方針。
- 初回は翻訳用データのダウンロードが必要。対応端末で機能が利用できることを初期に検証する。
- PC版Chromeを最初の対応環境とし、スマートフォンでの翻訳対応は約束しない。
- 外部サービスの無料枠到達時は原文で続けると合意した。現方式ではその無料枠を消費しないため、主に端末での利用不可・ダウンロード失敗・翻訳失敗への対応として原文での継続を設計する。
- Chromeで十分な品質・速度を得られない場合は、代替案を本人と再検討する。無断で有料APIや外部送信に切り替えない。

### 主なリスクと対策案

- 翻訳機能の利用不可・品質不足：環境準備の初期に検証し、原文表示を残す。結果により本人と方式を見直す。
- 履歴の混入・意図しない参照：部屋の識別をすべての取得・送信処理で確認し、別室のデータが返らないことを検証する。
- ルームIDの漏えい：ランダムな12文字を発行し、参加・送信の連続操作を制限する初期実装。ID失効方法は未決定で、アカウントによる本人確認の代わりとは扱わない。
- 通信・保存の失敗：入力文を保持して失敗を案内する。送信識別子で同じ送信を重複保存しない。未送信の文章がある退室操作には確認を出す。
- 無料公開環境の制約：ローカルの完成と公開を分け、公開先の利用条件・保存の継続性を確認してから採用する。

### テスト・検証の方針と結果

- JUnit等で部屋の照合、入力検証、保存・取得、部屋間の分離を確認する。
- 複数の独立したブラウザ利用状態で、2人・複数人の会話と入退室を確認する。
- 日本語・英語を読む参加者が同じ会話を読み、原文も確認できることを実機で検証する。
- 不正なID、空欄、翻訳用データの取得失敗、翻訳不可、通信・保存失敗を確認する。
- テストには架空の会話を使い、実際の友人との履歴と分ける。
